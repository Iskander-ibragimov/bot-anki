# Telegram-бот интервальных повторений слов (RU → EN) — дизайн

Дата: 2026-09-29 · Статус: на ревью

## 1. Цель и рамки

**Продукт:** Telegram-бот (только чат, без Mini App) для изучения английских слов русскоязычными пользователями методом интервальных повторений уровня AnkiDroid (FSRS-6, 4 кнопки оценки, шаги обучения).

**Для кого:** массовая аудитория, продукт на рынок. Интерфейс RU и EN.

**Бюджет:** один арендованный VPS (~$4–6/мес) + только бесплатные сервисы. Монетизации нет, но модуль прав (`entitlements`) заложен.

**Критерии успеха MVP:**
- Пользователь за ≤60 сек проходит онбординг и видит первую карточку.
- Нажатие кнопки оценки → следующая карточка за ≤300 мс (p95).
- Интервалы на кнопках совпадают с Anki (FSRS-6, те же шаги) на эталонных сценариях.
- Ежедневное напоминание приходит в выбранное пользователем местное время ±1 мин.
- Работает на VPS с 2 ГБ RAM при 5 000 активных пользователей в день.

**Не входит в MVP (YAGNI):** Mini App, импорт .apkg, свои шаблоны карточек, картинки, соревнования, оплата, персональный оптимизатор FSRS (этап 2).

## 2. Пользовательские сценарии

### 2.1 Онбординг `/start`
1. Язык интерфейса из `language_code` Telegram (ru → RU, иначе EN), меняется в настройках.
2. Экспресс-тест уровня: 10 слов разной частотности, «знаю / не знаю» → уровень A1–B2.
3. Цель в день: 5 / 10 / 20 новых слов.
4. Время напоминания: пользователь выбирает время, бот спрашивает «сколько у вас сейчас?» (кнопки с часами) → смещение часового пояса.
5. Предлагается колода под уровень → сразу первая карточка.

### 2.2 Сессия повторения (`/learn` или кнопка из пуша)
Сессия идёт в **одном сообщении**, которое бот редактирует.

- **Лицевая сторона:** слово, транскрипция, `🔊` (голосовое сообщение), `Показать ответ`.
- **Оборот:** перевод, часть речи, пример EN + RU, 4 кнопки с реальными интервалами:

| Кнопка | Цвет | Новая карточка (дефолт) | На повторении |
|---|---|---|---|
| Снова | красная | `<1м` | `10м` (переучивание) |
| Трудно | серая | `<6м` | FSRS, короче «Хорошо» |
| Хорошо | зелёная | `<10м` | FSRS |
| Легко | синяя | `4д` | FSRS с бонусом |

Цветные кнопки — через стили кнопок Bot API (9.4+); fallback — эмодзи 🟥⬛🟩🟦 в подписи.

- **Очередь сессии (как Anki):** (1) карточки на шагах, чьё время подошло; (2) повторения по сроку; (3) новые в пределах дневного лимита, вперемешку с повторениями.
- Если в очереди пусто, а карточка на шаге вернётся менее чем через 60 сек — бот пишет «Следующая через N сек» и сам присылает карточку; есть кнопка «Показать сейчас». Если дольше — сессия завершается итогом.
- Если пользователь ушёл, а карточки на шагах ждут — один пинг «N карточек на закреплении — 1 минута».
- Команда `/undo` — отмена последней оценки (как в Anki).

### 2.3 Добавить своё слово
Пользователь пишет в чат слово/фразу (или список через перенос строки, до 20). Бот собирает карточку: Free Dictionary API (транскрипция, часть речи, пример, аудио) + LLM (перевод на русский, перевод примера). Превью с кнопками `✅ Добавить` `✏️ Изменить` `✖️`. Слово попадает в колоду «Мои слова».

### 2.4 Колоды
- `/decks` — каталог: A1, A2, B1, B2, «Путешествия», «IT и работа», «Разговорные фразы»; мои колоды со счётчиками «новые / к повтору».
- `/gen <тема>` — AI-колода 10–30 слов, превью списка, `Добавить колоду`. Лимит 3 генерации в день на пользователя.

### 2.5 Напоминания
- Одно в день в выбранное время: «12 карточек ждут · ~4 мин» + `Начать`. Если к повтору 0 — не отправляется.
- Вечером (20:00 местного), если сегодня не занимался и серия ≥ 2 дней — одно «спасём серию».
- Тихие часы 23:00–08:00: никаких пингов, кроме выбранного пользователем времени.

### 2.6 Статистика `/stats`
Серия дней, выучено слов, удержание за 30 дней, прогноз нагрузки на 7 дней, тепловая карта за год — PNG (matplotlib).

### 2.7 Настройки `/settings`
Язык интерфейса; режим удержания Лёгкий 85% / Оптимальный 90% / Интенсив 95% (= desired retention); новых слов в день; время напоминания; направление EN→RU / RU→EN / оба; озвучка авто/вручную.

## 3. Архитектура (C4)

### 3.1 Контекст
Ученик ↔ Telegram ↔ **Бот-система** → бесплатный LLM API, Free Dictionary API. Контент-админ (владелец) загружает колоды CSV командой в боте и получает бэкапы.

### 3.2 Контейнеры (один VPS, Docker Compose)

| Контейнер | Технология | Назначение |
|---|---|---|
| `app` | Python 3.12, aiogram 3, long polling | Бот + планировщик + фоновые задачи в одном asyncio-процессе |
| `db` | PostgreSQL 16 | Все данные, сессии, очередь задач |
| Piper TTS | библиотека внутри `app` | Офлайн-озвучка английского |

Решения экономии:
- **Long polling** вместо webhook — не нужны домен и HTTPS.
- **Нет Redis** — сессии и очередь в PostgreSQL (`SELECT … FOR UPDATE SKIP LOCKED`).
- **Один процесс** — модули изолированы, при росте выносятся в отдельные процессы без переписывания.
- VPS за рубежом (DE/NL), 2 ГБ RAM, 1–2 vCPU: бесплатные AI-API часто недоступны с российских IP.

### 3.3 Компоненты (модули в `app/`)
Зависимости только вниз по слоям; проверяет `import-linter`.

| Слой | Модуль | Ответственность |
|---|---|---|
| Интерфейс | `bot/handlers` | Команды, колбэки, текст. Только парсинг + вызов сервисов |
| | `bot/views` | Тексты, клавиатуры, i18n (RU/EN, fluent-файлы) |
| Приложение | `review` | Сессия, очередь, шаги, undo, идемпотентность |
| | `content` | Каталог, добавление слова, AI-колоды |
| | `reminders` | Ежеминутный тик: пуши, пинги шагов, «спасём серию» |
| | `stats` | Метрики и PNG |
| | `users` | Онбординг, настройки, часовой пояс |
| | `entitlements` | Лимиты (генерации/день). Точка для будущего Stars |
| Домен | `srs` | Обёртка над `py-fsrs`: `preview(card, now) → 4 исхода`, `grade(card, rating, now)`. Чистые функции, без I/O |
| Инфраструктура | `db`, `jobs`, `llm`, `dictionary`, `tts`, `tg` | Адаптеры за протоколами; в тестах — фейки |

### 3.4 Ключевой поток: нажатие «Хорошо»
1. `callback_query` с данными `g:<card_id>:<reps>:<rating>`.
2. Хэндлер: если `reps` не совпадает с текущим у карточки — нажатие устарело, игнор (идемпотентность).
3. `review.grade()` в одной транзакции: `srs.grade()` → вставка в `review_log` → обновление `cards` → обновление серии.
4. `review.next()` выбирает следующую карточку → `views` → `editMessageText`.
5. Если у слова нет `audio_file_id` — задача `tts` в очередь.

## 4. Данные

```
users(id, tg_id UNIQUE, lang, tz_offset_min, remind_at TIME, new_per_day,
      retention, direction, streak, last_study_date, active, created_at)
decks(id, owner_id NULL, kind[catalog|ai|custom], title_ru, title_en, level, created_at)
notes(id, deck_id, word, ipa, pos, translation, example_en, example_ru,
      audio_file_id NULL, UNIQUE(deck_id, word))
user_decks(user_id, deck_id, added_at, PRIMARY KEY(user_id, deck_id))
cards(id, user_id, note_id, direction[en_ru|ru_en], state[new|learning|review|relearning],
      step, stability, difficulty, due TIMESTAMPTZ, reps, lapses, last_review,
      UNIQUE(user_id, note_id, direction))
review_log(id, card_id, user_id, rating, state_before, reviewed_at,
      elapsed_days, scheduled_days, duration_ms)          -- append-only
sessions(user_id PK, message_id, current_card_id, side[front|back], started_at)
jobs(id, kind, payload JSONB, run_at, attempts, locked_at, done_at, error)
```
Индексы: `cards(user_id, due)`, `jobs(run_at) WHERE done_at IS NULL`, `users(remind_at)`.

Карточки создаются лениво: при добавлении колоды — только `user_decks`; строка `cards` появляется, когда новая карточка впервые попадает в сессию.

## 5. Алгоритм (FSRS-6 через `py-fsrs`)
- Параметры: дефолтные FSRS-6; learning steps `1m, 10m`; relearning `10m`; desired retention из настроек (0.85/0.90/0.95); max interval 36 500 дн; fuzz включён.
- Подписи кнопок: `srs.preview()` возвращает 4 будущих `due`, форматируются как `<1м`, `10м`, `1д`, `2,3мес`.
- Сиблинги: при `direction=both` вторая карточка того же слова не показывается в день, когда первая уже была.
- Граница дня: 04:00 местного времени.
- Этап 2: персональный оптимизатор (`fsrs-optimizer`) ночью на отдельной машине/по запросу, когда у пользователя ≥ 1 000 повторов.

## 6. Контент
- Каталожные колоды (≈ 3 000 слов суммарно) генерируются **один раз на этапе разработки** скриптом `scripts/build_decks.py` (частотные списки + LLM для переводов/примеров), выборочно проверяются и коммитятся в `data/decks/*.csv`. Загружаются миграцией.
- Озвучка: Piper (`en_US-lessac-medium`) при первом показе → `sendVoice` → `file_id` сохраняется в `notes.audio_file_id`, дальше переиспользуется.
- LLM: провайдер-агностичный адаптер (OpenAI-совместимый HTTP). Первичный — бесплатный тариф (Gemini / Groq / OpenRouter free), конкретный выбор и лимиты фиксируются в плане. Ответ — строгий JSON по схеме, валидация pydantic.

## 7. Ошибки

| Ситуация | Реакция |
|---|---|
| Двойное/устаревшее нажатие | Проверка `reps` в callback-данных, игнор |
| Telegram 429 | Ждать `retry_after`; рассылка пушей ≤ 25 msg/сек |
| 403 (бот заблокирован) | `users.active=false`, пуши прекращаются |
| «message is not modified» / старое сообщение | Отправить новое сообщение сессии, обновить `sessions.message_id` |
| LLM недоступен / лимит | Данные словаря; если перевода нет — попросить ввести вручную |
| Free Dictionary не нашёл слово | Только LLM; если и он недоступен — ручной ввод |
| TTS ошибка | Карточка без 🔊, задача повторится (до 3 попыток) |
| Падение процесса | `restart: always`; сессия восстанавливается из `sessions` |
| Потеря сервера | Ежедневно 03:00 UTC `pg_dump | gzip` → документ в чат админа (`ADMIN_TG_ID`) |

## 8. Тестирование
- **Юнит:** `srs` — эталонные последовательности оценок vs ожидаемые интервалы; очередь `review` с инъекцией часов; форматирование интервалов; i18n (все ключи есть в обоих языках).
- **Интеграционные:** PostgreSQL в Docker (pytest + testcontainers), хэндлеры с фейковым Telegram-клиентом, очередь `jobs` с конкурентными воркерами.
- **Сценарные:** онбординг → 10 карточек → «Снова» → возврат через 1 мин → пуш на следующий день.
- Покрытие ≥ 90% для `srs` и `review`, ≥ 70% в целом. CI — GitHub Actions (бесплатно).

## 9. Эксплуатация
- Деплой: `git pull && docker compose up -d --build` на VPS; скрипт `deploy.sh`.
- Конфиг через `.env`: `BOT_TOKEN`, `DATABASE_URL`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `ADMIN_TG_ID`.
- Логи: stdout JSON, `docker logs`; админ-команда `/admin stats` (DAU, повторы за сутки, ошибки).

## 10. Этапы
1. **MVP:** онбординг, каталожные колоды, сессия с 4 кнопками и шагами, напоминания, настройки, добавление своего слова, AI-колоды `/gen`, текстовый `/stats` (серия, выучено, к повтору), загрузка колод CSV админом, бэкапы.
2. **v1.1:** `/stats` с PNG-графиками (прогноз, тепловая карта), режим ввода ответа.
3. **v2:** персональный оптимизатор FSRS, импорт CSV/.apkg, Mini App, монетизация через Stars.
