# Telegram-бот интервальных повторений слов (RU → EN) — дизайн

Дата: 2026-09-29, ред. 2026-09-30 (Cloudflare Workers, кнопки сразу, накопительный прогресс, ссылки) · Статус: на ревью

## 1. Цель и рамки

**Продукт:** Telegram-бот (только чат, без Mini App) для изучения английских слов русскоязычными пользователями методом интервальных повторений уровня AnkiDroid (FSRS-6, 4 кнопки оценки, шаги обучения).

**Для кого:** массовая аудитория, продукт на рынок. Интерфейс RU и EN.

**Бюджет:** $0. Хостинг — бесплатный тариф Cloudflare Workers + D1. Путь роста — Workers Paid $5/мес без изменения кода. Монетизации нет, модуль прав (`entitlements`) заложен.

**Критерии успеха MVP:**
- Онбординг ≤ 60 сек до первой карточки.
- Нажатие оценки → следующая карточка ≤ 300 мс p95 (без сети Telegram).
- Интервалы на кнопках совпадают с FSRS-6 эталоном: новая карточка `<1м / <6м / <10м / 8д`.
- Напоминание приходит в выбранное местное время, опоздание ≤ 2 мин.
- Бесплатный тариф держит ~300 активных пользователей в день; при превышении лимитов бот предупреждает админа заранее (80 %).

**Не входит в MVP (YAGNI):** Mini App, импорт .apkg, свои шаблоны, картинки, соревнования, оплата, персональный оптимизатор FSRS, разбор содержимого ссылок.

## 2. Пользовательские сценарии

### 2.1 Онбординг `/start`
1. Язык интерфейса из `language_code` (ru/uk/be/kk → RU, иначе EN).
2. Экспресс-тест: 10 слов, «знаю / не знаю» → A1–B2 (0–2 A1, 3–5 A2, 6–8 B1, 9–10 B2).
3. Новых слов в день: 5 / 10 / 20.
4. Время напоминания.
5. «Сколько у вас сейчас?» → смещение часового пояса (кратно 30 мин, корректно через полночь).
6. Колода под уровень → первая карточка.

### 2.2 Сессия повторения — одна карточка в чате, все кнопки сразу
В чате всегда одна карточка: после оценки бот присылает следующую карточку **новым сообщением** и удаляет предыдущее (вместе с её голосовым). Редактировать то же сообщение нельзя: Telegram оставляет спойлер открытым после правки. Если старое сообщение удалить нельзя (старше 48 ч), с него снимаются кнопки. Отдельного шага «Показать ответ» нет.

```
🔵 4 · 🔴 1 · 🟢 12
✅ borrow → через 11 дн. (было 2 дн.)        ← итог предыдущей оценки
reliable
/rɪˈlaɪəbl/ · adj
▒▒▒▒▒▒▒▒                                     ← спойлер: перевод
▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒                              ← спойлер: пример EN — RU
🌿 Учу · память ~2 дн. · повтор №3
🔗 youtube.com                               ← если к слову прикреплена ссылка
[Снова <1м]   [Трудно <6м]
[Хорошо <10м] [Легко 8д]
[🔊]          [↩️ Отменить]
```

- Перевод и пример — `<tg-spoiler>`: открываются тапом на стороне клиента, запрос к боту не нужен. Одна оценка = один запрос к Worker (вдвое экономит лимиты).
- Кнопки 2×2, `style`: Снова=`danger`, Трудно=без стиля, Хорошо=`success`, Легко=`primary`. Текст `"{label} {interval}"`.
- Направление RU→EN: крупно перевод, под спойлером английское слово, транскрипция и пример.
- Предпросмотр ссылок в сообщении сессии отключён (`link_preview_options.is_disabled`).
- **Очередь (как Anki):** (1) карточки на шагах с наступившим сроком; (2) повторения по сроку дня; (3) новые в пределах дневного лимита, равномерно между повторениями. Если показывать нечего, а шаговая карточка наступит ≤ 60 сек — показываем её сразу (learn-ahead). Иначе — итог сессии.
- Карточки на шагах ждут, пользователь ушёл → один пинг (cron) «N карточек на закреплении — 1 минута».
- `/undo` и кнопка ↩️ — отмена последней оценки.

### 2.3 Накопительный прогресс
- **Интервалы растут от повтора к повтору** по FSRS-6: пример «Хорошо» подряд — 10м → 2д → 11д → ~1,2 мес → …
- **Строка прогресса на карточке** — стадия и «память»:
  - 🌱 Новое — ещё не видели;
  - 🌿 Учу — на шагах или интервал < 7 дн.;
  - 🌳 Знаю — интервал 7–20 дн.;
  - 🏆 Выучено — интервал ≥ 21 дн.
  «Память ~N дн.» = текущий интервал карточки (для переучивания — сохранённая стабильность FSRS).
- **Итог предыдущей оценки** первой строкой следующей карточки:
  - рост: `✅ borrow → через 11 дн. (было 2 дн.)`;
  - шаг: `borrow → через 10 мин`;
  - провал выученного: `↻ borrow → через 10 мин · память сохранена ~4 дн.`
- **«Снова» не обнуляет прогресс.** FSRS снижает стабильность, но не до нуля; после переучивания интервал продолжает расти от сохранённой памяти. Повторное добавление уже изучаемого слова или колоды прогресс не трогает.
- **Итог дня** на экране завершения: `Сегодня: 24 повтора · +3 выучено` и `Всего: 🏆 37 · 🌳 20 · 🌿 14 · 🌱 429`.
- `/stats` — всё накопленным итогом: серия, выучено всего, распределение по стадиям, повторов всего и за 30 дн., удержание за 30 дн., прогноз на 7 дн. (текстом).

### 2.4 Свои слова и ссылки
Пользователь пишет в чат слово, фразу или список (до 20 строк). Правила ссылок (URL берутся из entities `url` и `text_link`):
- ссылка **на той же строке**, что слово → прикрепляется к этому слову;
- ссылка **отдельной строкой** → ко всем словам сообщения без своей ссылки;
- сообщение **только из ссылки** → бот запоминает её на 10 минут и просит прислать слова; следующие слова получат эту ссылку;
- у одного слова хранится одна ссылка (первая); ссылки только `http(s)`, длина ≤ 512.

Карточка собирается из Free Dictionary API (транскрипция, часть речи, пример, аудио) и LLM (перевод, перевод примера). Превью `✅ Добавить` `✏️ Изменить` `✖️` показывает и 🔗. Слова попадают в колоду «Мои слова». Дубликаты (в «Моих словах» или подписанных колодах) не создаются; если у дубликата пришла новая ссылка, а своей у него нет — ссылка добавляется к существующей карточке без сброса прогресса.

### 2.5 Колоды
- `/decks` — каталог A1, A2, B1, B2, «Путешествия», «IT и работа», «Разговорные фразы»; мои колоды со счётчиками.
- `/gen <тема>` — AI-колода 10–30 слов, превью, `Добавить колоду`. Лимит 3 в день.

### 2.6 Напоминания
- Одно в день в выбранное время, если есть что повторять: `⏰ 12 карточек · ~4 мин` + `▶ Начать`.
- 20:00 местного, не занимался сегодня, серия ≥ 2 → «спасём серию».
- Тихие часы 23:00–08:00 для пингов; своё время напоминания пользователь выбирает сам.

### 2.7 Настройки `/settings`
Язык; режим удержания Лёгкий 85 % / Оптимальный 90 % / Интенсив 95 %; новых в день; время напоминания; направление EN→RU / RU→EN / оба; автоозвучка.

## 3. Архитектура (C4)

### 3.1 Контекст
Ученик ↔ Telegram ↔ **Бот-система (Cloudflare)** → бесплатный LLM API (Groq, резерв OpenRouter), Free Dictionary API. Админ загружает колоды CSV в боте. GitHub Actions — сборка колод, озвучка, деплой, еженедельный экспорт БД.

### 3.2 Контейнеры

| Контейнер | Технология | Назначение |
|---|---|---|
| `worker` | Cloudflare Worker, TypeScript, grammY, ts-fsrs | `fetch` — webhook Telegram; `scheduled` — cron раз в минуту: напоминания, пинги, очередь задач |
| `db` | Cloudflare D1 (SQLite) | Все данные, сессии, очередь задач, превью |
| CI | GitHub Actions (бесплатно) | Тесты, деплой `wrangler deploy`, сборка и озвучка колод (Piper), еженедельный `wrangler d1 export` |

Лимиты бесплатного тарифа и как мы в них укладываемся:

| Лимит | Значение | Решение |
|---|---|---|
| Запросы | 100 000/день | 1 запрос на оценку (спойлер вместо «Показать ответ») |
| CPU | 10 мс/вызов | Бот и планировщик FSRS создаются один раз на изолят; без тяжёлых библиотек |
| Подзапросы (fetch + D1) | 50/вызов | Webhook ≤ 8 обращений к D1 (через `batch`) + ≤ 3 к Telegram; cron — ≤ 35 отправок за тик, остаток в следующий |
| После ответа | `waitUntil` ≤ 30 сек | Вызовы LLM/словаря идут после мгновенного ответа «Ищу…»; ретраи — через таблицу `jobs` из cron |
| D1 записи | 100 000 строк/день | ≈ 5 строк на оценку; счётчик в `usage_daily`, предупреждение админу на 80 % |
| D1 чтения | 5 млн строк/день | Индексы на все выборки очереди |
| Cron | 5 на аккаунт | Используем 1: `* * * * *` |

- Webhook защищён `secret_token` (заголовок `X-Telegram-Bot-Api-Secret-Token`).
- Бэкапы: D1 Time Travel (восстановление на момент в пределах 7 дней) + еженедельный экспорт в артефакт GitHub Actions.

### 3.3 Компоненты (модули `src/`)
Зависимости только вниз; проверяет `dependency-cruiser`.

| Слой | Модуль | Ответственность |
|---|---|---|
| Интерфейс | `bot/handlers` | Команды, колбэки, текст. Только парсинг + вызов сервисов |
| | `bot/views` | Тексты, спойлеры, клавиатуры 2×2, i18n RU/EN |
| Приложение | `review` | Очередь, оценка, undo, learn-ahead, итог оценки, прогресс |
| | `content` | Каталог, свои слова, разбор ссылок, AI-колоды |
| | `reminders` | Тик cron: напоминания, пинги, лимит отправок |
| | `stats` | Накопительная статистика |
| | `users` | Онбординг, настройки, часовой пояс, границы дня |
| | `entitlements` | Лимиты (генерации/день) |
| | `admin` | `/admin stats`, загрузка CSV, контроль лимитов |
| Домен | `srs` | Обёртка ts-fsrs: `preview`, `grade`, `stage`, `formatInterval`. Чистые функции |
| Инфраструктура | `db`, `jobs`, `llm`, `dictionary`, `tg` | Адаптеры; в тестах фейки |

### 3.4 Поток: нажатие «Хорошо»
1. `callback_query` `g:<card_id>:<reps>:<rating>`.
2. `reps` ≠ текущему → «кнопка неактуальна» (ответ на callback), без изменений.
3. `review.grade()`: `srs.grade()` → один `db.batch([update card, insert review_log, update user, upsert usage_daily])`.
4. `review.next()` выбирает следующую карточку → `views` с итогом предыдущей оценки → `editMessageText`.
5. Итого ≤ 3 обращения к D1 и 2 к Telegram.

## 4. Данные (D1 / SQLite)

```
users(id, tg_id UNIQUE, lang, tz_offset_min, remind_at TEXT 'HH:MM', new_per_day, retention,
      direction, autoplay, streak, last_study_day TEXT, active, onboarding_step,
      gens_day, gens_count, pending_url, pending_url_at,
      last_daily_push_day, last_evening_push_day, last_step_ping_at, last_review_at, created_at)
decks(id, owner_id NULL, kind[catalog|ai|custom], title_ru, title_en, level, total)
notes(id, deck_id, word, ipa, pos, translation, example_en, example_ru,
      audio_file_id NULL, audio_url NULL, source_url NULL, UNIQUE(deck_id, word))
user_decks(user_id, deck_id, added_at, PRIMARY KEY(user_id, deck_id))
cards(id, user_id, note_id, direction, state[new|learning|review|relearning], step,
      stability, difficulty, due INTEGER(ms), last_review INTEGER, scheduled_days,
      reps, lapses, buried_day TEXT NULL, UNIQUE(user_id, note_id, direction))

      interval_after_ms, reviewed_at, undone)
sessions(user_id PK, chat_id, message_id, card_id, last_feedback TEXT)
previews(id, user_id, kind[add|gen], payload TEXT(JSON), created_at)

```
Индексы: `cards(user_id, state, due)`, `users(active, remind_at)`, `jobs(done_at, run_at)`, `jobs(dedup_key) WHERE done_at IS NULL`.

Карточки каталога создаются лениво: при подписке — только `user_decks`, строка `cards` при первом показе новой карточки.

## 5. Алгоритм (FSRS-6 через ts-fsrs)
- `request_retention` из настроек (0.85/0.90/0.95), `maximum_interval=36500`, `enable_fuzz=true` (кроме превью), `enable_short_term=true`, `learning_steps=['1m','10m']`, `relearning_steps=['10m']`, параметры по умолчанию.
- Подписи кнопок — `repeat()` (все 4 исхода) без fuzz.
- Сиблинги: при «оба направления» вторая карточка слова скрывается до следующего дня.
- Граница дня 04:00 местного.
- Стадии и «память» — из `scheduled_days` / стабильности (§2.3).

## 6. Контент и озвучка
- Каталог (~3 000 слов) генерируется один раз скриптом `scripts/build-decks.ts` (частотные списки + LLM), выборочно проверяется, коммитится в `data/decks/*.csv`.
- Озвучка каталога — в GitHub Actions: Piper `en_US-lessac-medium` → OGG/Opus → `sendVoice` в чат админа → `file_id` записываются в seed-миграцию. В рантайме TTS нет.
- Свои слова: `audio_url` из Free Dictionary → `sendVoice` по URL (Telegram скачивает сам) → кешируем `file_id`. Нет аудио — кнопка 🔊 скрыта.
- LLM: OpenAI-совместимый адаптер, провайдеры по порядку из `LLM_PROVIDERS`, ответ — строгий JSON по схеме (zod). Всё падает → ручной ввод перевода.

## 7. Ошибки

| Ситуация | Реакция |
|---|---|
| Устаревшее нажатие | `reps` в callback, «кнопка неактуальна» |
| Telegram 429 | Отправка → `jobs` с `run_at = now + retry_after` |
| 403 (бот заблокирован) | `users.active = 0` |
| Сообщение сессии не редактируется | Новое сообщение, обновить `sessions.message_id` |
| LLM/словарь недоступны или > 25 сек | Ответ «Не получилось, пришлите перевод сами»; ретрай не делаем |
| Лимит D1 исчерпан | Бот отвечает «Технический перерыв до 03:00 МСК» (ошибка D1 перехватывается), админ уже предупреждён на 80 % |
| Невалидная ссылка / не http(s) / > 512 | Игнорируется, слово добавляется без ссылки |
| Потеря данных | D1 Time Travel 7 дней + еженедельный экспорт |

## 8. Тестирование
- Vitest + `@cloudflare/vitest-pool-workers` (реальный workerd и D1 в тестах).
- **Юнит:** `srs` (эталон `<1м/<6м/<10м/8д`, рост интервалов, «Снова» не обнуляет память, стадии), форматирование, разбор ссылок, i18n (ключи совпадают — проверяет TypeScript).
- **Интеграционные:** сервисы на D1, число обращений к D1 на webhook ≤ 8 (счётчик-обёртка), cron ≤ 35 отправок.
- **Сценарные:** онбординг → 10 карточек → «Снова» → возврат → итог дня → следующий день 09:00 ровно один пуш → интервалы выросли.
- Покрытие ≥ 90 % `srs` и `review`, ≥ 70 % в целом.

## 9. Эксплуатация
- Деплой: push в `main` → GitHub Actions → `wrangler d1 migrations apply` + `wrangler deploy`.
- Секреты: `BOT_TOKEN`, `WEBHOOK_SECRET`, `ADMIN_TG_ID`, `LLM_PROVIDERS` — через `wrangler secret`.
- `/admin stats`: активные за день, повторы, оценка использования лимитов, ошибки jobs.

## 10. Этапы
